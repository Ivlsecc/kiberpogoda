# Задача 3 — мониторинг киберугроз

Собирает публикации из публичных Telegram-каналов и превращает их в структурированные
события: тип, сущности (компании/домены/CVE), дубли, сопоставление об одном событии между
источниками, первоисточник, значимость и динамика активности.

Два слоя обработки. Базовый — правила (regex-маркеры с весами): работают офлайн, без ключей,
полностью объяснимы, и служат baseline для проверки ИИ. Поверх — опциональный локальный LLM
через Ollama (флаг `--llm`): берётся там, где правила слабее — нюансы типа события и
извлечение незнакомых названий-жертв. Локальный принципиально: threat-intel данные
чувствительны и не должны уходить во внешний API. Нет Ollama — всё молча работает на правилах.

## Запуск

```bash
pip install -r requirements.txt

python src/scrape.py --limit 40   # (опц.) собрать свежие посты из каналов config.json;
                                  # нет доступа к t.me — уже лежит data/raw_posts.jsonl (80 постов)
python src/pipeline.py            # обработка потока (базовый слой, офлайн)

ollama pull qwen2.5:7b            # (опц.) то же с локальным ИИ
python src/pipeline.py --llm

python src/evaluate.py            # качество классификатора (--llm — сравнение с LLM)
python tests/test_pipeline.py     # тесты
```

## Результаты (output/)

- `posts.jsonl` — обработанные посты: тип, сущности, дубли, кластер события, значимость
- `events.db` — то же в SQLite (`SELECT * FROM posts WHERE significance>0.7`)
- `activity.json` — динамика по дням/типам, дни-всплески, топ упоминаемых компаний
- `task1_signals.json` — агрегаты упоминаний отслеживаемых компаний → сигналы O/I для Задачи 1
- `evaluation.json` — метрики качества классификатора

## Качество

Классификатор проверен на ручной разметке (`data/gold_labels.json`, 40 постов). Правила дают
accuracy ≈ 0.65, macro-F1 ≈ 0.49 с понятными слабыми местами (ransomware, data_leak, phishing) —
это и есть повод для LLM-слоя: `evaluate.py --llm` прогоняет локальную модель на той же разметке
и показывает, где ИИ лучше правил и где ошибается сам.

## Ограничения

- Для демо взяты публичные новостно-аналитические infosec-каналы (сообщают об инцидентах), а не
  торговые площадки. Источник задаётся в `config.json` — аналитик ставит свои авторизованные.
- Сбор строго пассивный: читаем веб-превью `t.me/s/`, в каналы не вступаем, ничего не пишем,
  доступы и дампы не приобретаем.
- Доступ к t.me зависит от сети, поэтому реально собранные данные приложены и весь пайплайн
  воспроизводится офлайн.
- Правила — высокая точность, но не полнота; локальный LLM повышает полноту ценой скорости.
  Метки gold-набора ручные и местами спорные (мультиклассовость).
